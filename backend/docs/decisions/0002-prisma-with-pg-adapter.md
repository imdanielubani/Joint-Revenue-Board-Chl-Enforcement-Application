# ADR-0002: Prisma 7 with the node-postgres driver adapter

**Status:** accepted (14 Oct 2026, project owner)

## Context

`CLAUDE.md` makes Prisma the default ORM and migration tool. The existing
`iteime_backend/` uses raw `pg` with hand-written SQL migrations. The project
owner chose Prisma for `backend/`.

On 14 Oct 2026, the `latest` npm tag of `prisma` pointed to a release
candidate (`8.0.0-rc.22`); the newest stable release is 7.10.0.

## Decision

- Use `prisma` and `@prisma/client` 7.10.x, the stable release, with
  `@prisma/adapter-pg` (node-postgres). This is Prisma 7's driver-adapter
  model; no query-engine binary is needed at runtime.
- The generator is `prisma-client` (ESM, `.js` import extensions), with output
  in `src/generated/prisma`. The output is git-ignored and regenerated by
  `npm install` (postinstall) or `npm run prisma:generate`.
- The connection URL is set in `prisma.config.ts` (Prisma 7 no longer allows
  it in `schema.prisma`). It is optional there, so `generate` and `validate`
  work without a database.
- The schema has **no models** until Phase 2 settles data ownership.
- Migrations are created with `prisma migrate dev` (reviewed SQL, committed),
  and applied in deployed environments with `prisma migrate deploy`.
  Migrations are never applied automatically at server start-up.

## Consequences

- Prisma 7 needs Node.js ≥ 22.18 (`engines` in `package.json`).
- npm 11 blocks the install scripts of `@prisma/engines` and esbuild.
  `prisma generate`, `validate` and `format` were verified to work regardless.
  `migrate` commands download the schema engine on first use; this has not yet
  been exercised, because there are no models.
- Raw SQL remains possible (`$queryRaw`) where Prisma's query API doesn't fit.
