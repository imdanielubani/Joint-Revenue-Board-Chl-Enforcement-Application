# Requirements traceability

Maps the major requirements to their source, the owning system, the backend
domain, consumers, the data owner, API dependencies, status and open
decisions. Domains: [component-boundaries.md](../architecture/component-boundaries.md).
Owners: [data-ownership.md](../architecture/data-ownership.md). Questions:
[open-questions.md](open-questions.md).

## Status values (for this backend)

| Status          | Meaning                                                                                                                                     |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **tested**      | Implemented, with automated tests passing                                                                                                   |
| **implemented** | Code exists, without adequate tests                                                                                                         |
| **designed**    | A boundary and data proposal exist in the Phase 2 docs. **Not approved, not implemented.** No blocker prevents implementation once approved |
| **blocked**     | Can't be implemented until a listed decision or external input arrives                                                                      |
| **not started** | No design yet                                                                                                                               |

Phase 2 produced documentation only, so nothing moved past **designed** in
this phase. The only **tested** items are the Phase 1 foundation.

Abbreviations: **Mob** = mobile app; **Adm** = ITEIME Admin Dashboard;
**Mon** = Monitoring Dashboard; **ITM** = ITEIME backend.
