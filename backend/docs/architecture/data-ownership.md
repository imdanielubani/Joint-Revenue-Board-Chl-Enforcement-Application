# Data ownership

**Phase 2: architecture proposal, awaiting review.** Labels **[C] [R] [P] [Q]**
are explained in [system-context.md](system-context.md#how-to-read-the-labels).
Many owners below are **undecided**. Nothing is assumed to be ITEIME-owned just
because ITEIME needs to use it.

## Persistence strategies

How ITEIME treats each kind of data. Proposed in
[ADR-0007](../decisions/0007-chl-data-reference-strategy.md):

| Strategy     | Meaning                                                                                                                                                             |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **OWN**      | An ITEIME-owned record. ITEIME is the authority.                                                                                                                    |
| **REF**      | ITEIME stores only the external identifier (for example, a CHL agent ID or a transaction reference) and fetches details when needed.                                |
| **SNAPSHOT** | An immutable copy of what was shown or used _at the time of an event_, with `fetchedAt` and the source. It is evidence of what happened, never current truth.       |
| **CACHE**    | A refreshable copy with a freshness limit, for performance or offline use. Never authoritative; it is discarded or refreshed when stale. Needs approval (Q-CHL-14). |
| **DERIVED**  | Computed from other records: a query, a view, or a materialized aggregate. It has no lifecycle of its own.                                                          |
| **NONE**     | Not stored in ITEIME.                                                                                                                                               |

## Rules

- **[C]** CHL is authoritative for what it owns. A SNAPSHOT is evidence of the
  past; it is never served as current status.
- **[C]** Trip validity and payment status are never computed or set by ITEIME
  from client input (SRD §14; MON §7; `CLAUDE.md` §7).
- **[P]** Every SNAPSHOT and CACHE row records `source` and `fetchedAt`.
- **[P]** Timestamps are stored in UTC (`timestamptz`). Location context
  (coordinates, enforcement point, LGA) is stored where the event happened.
- **[P]** References to CHL entities use CHL's stable identifiers only
  (Q-CHL-13). A plate is a lookup key, never an identity.
